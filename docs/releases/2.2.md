# MagicDesk 2.2

Draft, not released. Final SteamOS installation, shell checks and comparative
benchmarks are pending.

## Shroot Performance

- Optional source-built musl/glibc provides direct syscall entry for supported
  operations. The installer carries the source hooks and patches and compiles
  inside Linux on the device. Android Bionic and the distribution's package-owned
  libc are not replaced. Shroot Base remains the unmodified-libc execution path.
- A shared local registry reuses builds matching the original interpreter/libc
  and entry ABI. Newly launched programs, including compatible nested-container
  programs, can select them without changing OCI image layers. Installed seccomp
  filters retain kernel syscall admission; library selection alone does not
  guarantee the unfiltered direct-entry speedup.
- Filesystem and descriptor handling reduce repeated path work, metadata
  bookkeeping and cross-thread replies. Writable overlays share the native-name
  path while retaining hardlink, copy-on-write, permission and watch semantics.
  These runtime improvements also benefit Shroot Base.

## Networking And Compatibility

- Shroot launches share network selection, port publication and DNS policy.
  Docker and Podman can use the supported logical nftables bridge/NAT path,
  including TCP/UDP published ports, outbound traffic and container peers.
  Docker's documented nftables configuration no longer requires a userland proxy.
  Unsupported rules remain explicit errors, not successful no-ops.
- Legacy X11 MIT-SHM can attach Shroot's virtual SysV shared memory to the
  embedded server through a scoped FD bridge. SteamOS's software profile uses
  Zink over Lavapipe without disabling shared-memory presentation.
- Fixes cover debugger signal delivery, protected proc access, service filesystem
  access and temporary-file writer lifetimes. Guest process limits are enforced
  within the launch; cgroup controller limits remain permissive.
- Direct entry no longer reports synthetic EINTR for a native plan cancelled
  before execution, or leaves peers unable to submit requests after JIT memory
  repair. These fixes cover interrupted builds and Qt tooling without disabling JIT.
- Queued direct-entry requests release their reservation before publishing a
  barrier stop, avoiding a JIT/descriptor-owner deadlock. Initial argv/environment
  layout now follows Linux, fixing Steam's startup overread at the final argument.
  Selected-directory `O_TMPFILE` preserves the provider's unsupported-operation
  error, so Flatpak can use its normal named-file fallback.
- Non-link paths inside mounted proc filesystems return `EINVAL` from `readlink`,
  preserving normal `realpath` traversal during bubblewrap sandbox setup.
- Namespace-file descriptors retain their bind-mount paths instead of exposing
  anonymous carrier names. Synthetic sysfs views include the standard empty
  directories used by Flatpak, without exposing additional host devices.
  CPU/NUMA topology remains available through a shared read-only native sysfs
  projection, including graphical sessions with gamepad support.
- User namespace quotas enforce `user.max_user_namespaces` across creators and
  ancestors, including final-FD release. NPROC accounting no longer pins dead
  namespaces; quota pressure also collects entries reaped by native fast waits.
  Proc exposes the actual fixed inotify limits. These changes allow
  the tested SteamOS Flatpak Chromium to start with its sandbox intact; GPU
  acceleration and the FUSE document portal remain separate limitations.

## Linux Installation

- Recipes prefer official ARM64 rootfs archives where available. SteamOS uses
  Valve's ARM64 recovery image, updates its configured repositories and provides
  nested Plasma launchers with software or compatible Turnip graphics.
- Libc builds run in the installed environment, without a full-environment copy.
  One compiler job setting applies to libc, Mesa/Turnip and KWin. When selected,
  libc preparation follows build-dependency installation, before fresh graphics
  compiler launches.
- Current network copies the selected executor's Android DNS addresses once.
  Resume retains the environment and DNS without downloading the rootfs again.
  Source extraction does not attempt to restore archive owners on Android build
  bindings; image imports retain their metadata-preserving behavior.
- Administrative setup uses the selected root account's home rather than the
  image user's home. GUI setup initializes a missing system Flatpak repository
  before user-session notifiers start; existing repositories are left alone.
- See [installation and resume](../shroot.md#linux-installer) and
  [enable acceleration later](../shroot.md#enable-after-installation).

## Console And Desktop

- Android shell commands use bundled upstream mksh, with persistent command
  recall across new interactive sessions. Termux and guest Linux keep their own
  shells. History does not preserve a live PTY across APK replacement.
- Console entry points share the existing-session picker without allocating an
  unwanted session. Phone console windows are visible in Running and Recents.
- Desktop property handling separates common Android policy from the authorized
  setter available on a particular firmware.

Existing format-17 Linux environments are retained. Shroot remains experimental
and is not a security boundary for untrusted images or programs. See
[coverage and limits](../shroot.md#coverage-and-limits).
